Research put to work on something I actually use

I build these for two reasons. The first is that they are fun — a paper deadline is not the only good reason to write code. The second is that carrying a research idea all the way to something a person actually uses is where you find out how it really applies, and what it really costs: a knowledge graph, an agent loop and a review gate all behave differently once someone depends on them daily, and none of those lessons arrive in a benchmark.

jojo

Jarvis fOr Job Organization — a local-first agentic assistant

Open app Guide Source

A job tracker you can talk to and hand work to. Connect a model and it answers questions about your search, drafts the follow-ups, and proposes the notes, tags and reminders you have not got round to. Everything runs on your own machine — no account, no backend, and records stay in the browser unless you point it at a cloud model yourself. Every change the agent wants to make is shown for review first, and goes through the same undo a button press does.

Knowledge graph Agentic orchestration Local-first React · TypeScript Apache-2.0

System architecture

Three layers, and the import rule that keeps them honest: dependencies point strictly downward. The interface knows about the service layer; the service layer knows about the graph; the graph knows about neither.
